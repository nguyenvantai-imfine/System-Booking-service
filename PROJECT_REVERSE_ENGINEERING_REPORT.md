## 13. Business rules evidenced

- Booking treats overlapping date intervals for the same room as conflicts, uses a 15-minute pending hold, and serializes room booking attempts with `sp_getapplock` (`booking_service.py:62-186`; `core/config.py`).
- Payment supports idempotency keys, OTP expiry/attempt checks and simulated IPN according to its service and test scripts. OTP is persisted as a raw code (`payment_service.py:57-74`; `models/giao_dich_otp.py:6-20`).
- Login and request dependencies reject LOCKED accounts but do not reject the distinct INACTIVE status (`user-service/src/models/tai_khoan.py:12-15`, `auth_service.py:94-103`, `api/dependencies.py:44-50`).
- Room availability filters by hotel/status/capacity; requested dates are not used to test booking overlaps (`room_service.py:296-320`).
- Hotel supports search, ownership checks, soft-delete and restore; creation can include child records (`hotel-service/src/services/hotel_service.py`).

## 14. Data flows

### Customer booking/payment

1. Customer search/detail requests go from browser to configured service URLs directly.
2. Checkout submits room/guest/date data to Booking.
3. Booking creates a pending record and hold; request data includes the selected room/price.
4. Browser submits payment details to Payment; Payment checks Booking status/hold but saves supplied amount/code/ID.
5. Browser requests OTP generation and verification or uses the sandbox IPN path.
6. Payment attempts to confirm Booking and publishes a notification event.
7. Notification consumes events, builds content, stores notification records, then uses mock or SMTP sender.
8. Browser navigates to the success page, which can use fallback data if the API fetch fails.

This is a source-derived intended path, **not an observed successful runtime flow**. The account attribution, amount verification, service auth, broker dependency and room-availability gaps above interrupt or weaken the chain.

### Hotel/room admin

Admin UI calls hotel/room APIs for list and mutation operations, receives JSON and updates local React state/refetches. Room listing supports server pagination/filtering; the UI sort control is not connected to ordering.
